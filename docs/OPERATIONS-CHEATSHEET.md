## Which service does what?

| Part                              | Think of it as                                             | Where to look                                                                                     |
| --------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Browser                           | Your editing desk: drafts, selection, local originals      | Website, browser Console/Network if needed                                                        |
| Git / GitHub                      | Code history and published project files                   | [Repository](https://github.com/EsteriT/Pokedex)                                                  |
| GitHub Pages                      | The website's public shop window                           | [Live website](https://esterit.github.io/Pokedex/)                                                |
| Actions: Deploy website           | Packs source into deployable pages and publishes them      | [Actions](https://github.com/EsteriT/Pokedex/actions)                                             |
| Supabase Auth                     | Checks Google sign-in and keeps sessions                   | [Pokedex dashboard](https://supabase.com/dashboard/project/pnuovoogfjzzlgmenhnq) → Authentication |
| Supabase Database                 | Saved binder/collection records and ownership rules        | Dashboard → Database; schema history in `supabase/migrations/`                                    |
| Supabase Storage                  | Actual uploaded artwork, privately stored                  | Dashboard → Storage → binder-artwork                                                              |
| Actions: Encrypted backend backup | Scheduled operator that makes and verifies recovery copies | Actions → Encrypted backend backup, once rolled out                                               |
| Cloudflare R2                     | Private cupboard holding encrypted recovery archives       | [Cloudflare](https://dash.cloudflare.com/) → R2 → pokedex-backups                                 |
| Healthchecks                      | Alarm when a backup fails or does not arrive               | [Healthchecks](https://healthchecks.io/) → Pokedex daily backup                                   |

Google OAuth app settings are in Google Cloud; Supabase uses that app for login. The Cloudflare agent OAuth authorization permits development tooling and is separate from the bucket-scoped R2 credentials the scheduled job needs.

| Folder                 | Purpose                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `src/`                 | Source pages/scripts/styles we edit. Backend adapter connects configured builds to Supabase.          |
| `preview/`             | Generated standalone pages, normally unconfigured/local. Rebuild, never edit directly.                |
| `dist/`                | Ignored deployable package generated by `build:pages`, then uploaded by Actions.                      |
| `scripts/`             | Build, tests, operator backup/encryption/recovery tools. These tools are not browser code.            |
| `.github/workflows/`   | Instructions GitHub's machines run.                                                                   |
| `supabase/migrations/` | Reviewed database schema/permission changes. Pushing code does not apply these automatically.         |
| `docs/`                | Durable project setup, tests and milestone records.                                                   |
| `.scratch/`            | Ignored temporary screenshots, test artifacts and local backup/recovery files; not permanent storage. |
| `.env.local`           | Ignored local private configuration. Never upload or paste it.                                        |

## If something breaks

| Symptom                                | First check                                                    | Next action                                                                                                              |
| -------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Website shows an old version           | Latest Deploy website run, branch pushed, hard refresh         | Check live route/config. Local `src`, preview and hosted builds can differ.                                              |
| Cannot sign in                         | Supabase Auth status/logs and Google provider                  | Check Google callback and allowed return URL against hosted rollout guide. Keep secrets private.                         |
| Saved cards missing on another browser | Same Google account? Was Save successful?                      | Preserve drafts/backups before refresh; inspect save error. Never reset/delete cloud data as a first fix.                |
| Save conflict                          | Another browser saved a newer revision                         | Preserve a portable backup of the draft, reload and reconcile. Don't blindly overwrite.                                  |
| Uploaded artwork missing               | Supabase Storage and Network request status                    | Check owner/session/file path. Don't make the bucket public to solve access errors.                                      |
| Sample card pictures load slowly       | Network panel image host, request timing and cache             | Catalogue artwork may use external hosts; R2 operator backups don't speed those images up.                               |
| Backup alert                           | Encrypted backend backup run and Healthchecks ping history     | Find last verified unexpired R2 archive; inspect generic failure stage, quota and credential expiry; retry after fixing. |
| No backup workflow ran                 | Actions schedule enabled? `BACKUPS_ENABLED=true`? main active? | Public schedules can disable after inactivity. Healthchecks catches the missing run.                                     |
| R2 archive cannot decrypt              | Correct archive's passphrase? Download complete?               | Retry download. Keep the original untouched. No password recovery exists.                                                |
| Account deletion interrupted           | Account data pending state and Supabase Storage                | Retry the documented deletion flow. Do not delete Storage metadata directly in SQL.                                      |

For a critical failure: **preserve evidence and the latest good backup, stop repeated destructive actions, and diagnose before restoring.** Don't share keys, raw user records, decrypted backups, Ping URLs or full environment files in public issues/chat.

## Routine checks

- **After changes:** local tests, deployment result, sign-in/Save/refresh and the affected user flow. Before database changes, make and verify a fresh backup.
- **After automation is live:** confirm each daily run is verified, the monitor is Up, and there is a recent unexpired R2 archive. A green deployment says nothing about backups.
- **Weekly:** check failure alerts, overdue R2 expiry, source artwork/egress/storage quotas and backup size; verify the notification email still reaches you. Remove expired manual/off-computer copies too.
- **Monthly and after backup-code changes:** a disposable local recovery drill. A file existing in R2 alone is not proof it can restore data.
- **Before credentials expire:** renew the scoped Supabase token/R2 credentials in the protected environment, run a verified manual workflow, then revoke old credentials. Keep old archive passphrases until those archives expire.
- **Billing:** inspect R2/Actions/Supabase usage. The accepted $5/month buffer is a budget, not a hard cutoff. Configure billing alerts.

## Daily backup controls (after rollout)

- **Run now:** repository → Actions → Encrypted backend backup → Run workflow → main. Use it before database migrations; verify the run and R2 retrieval/decryption result. While daily runs are intentionally disabled, check and re-pause the monitor afterward if needed: [a ping normally resumes paused Healthchecks monitoring](https://healthchecks.io/docs/configuring_checks/#pinging-a-paused-check).
- **Enable daily runs:** repository → Settings → Secrets and variables → Actions → Variables → repository variable `BACKUPS_ENABLED=true`. Then unpause the production Healthchecks check when acceptance passes.
- **Stop scheduled runs:** set `BACKUPS_ENABLED=false`. Pause Healthchecks only during an intentional outage; otherwise its alert is useful. Manual runs remain possible. Record why protection stopped.
- **Recover:** follow [account/operator recovery](ACCOUNT-DATA-AND-RECOVERY.md#recovery-drill). First test locally and reconcile deletion requests. There is no automated production restore button.

## Where secrets belong

GitHub environment **backup-production** holds the six secret names listed in [backup setup](AUTOMATED-BACKUPS.md#private-github-setup), with main-only deployment branches. They are not website settings. Your password manager holds independent recovery passphrases and credential records. Supabase stores the Google client secret; the browser only receives a public publishable key. Never add a private key to `src`, `preview`, `dist`, Git or chat.

Protect GitHub, Cloudflare, Supabase, Google and Healthchecks accounts with MFA and private recovery codes. Losing a passphrase makes its encrypted archive unusable; losing an API token can be fixed by issuing a replacement.

## What this beta does not promise

Manual Save is required; there is no automatic realtime synchronization. Daily backups can lose saved changes made since the last successful backup (normally up to a day, more during an outage). Seven-day archives expire with possible cleanup/provider delays. Operator archives exclude full Auth/configuration and don't preserve deleted-account ownership automatically. Browser originals/downloads stay on users' devices. Live catalogue/pricing, public sharing and print/image export remain future work. See [project overview](../README.md) and acceptance records for current scope.
